# Phase 01.5 — Frontend/backend workspace split

Status: Complete (2026-10-25)

## Decision

Keep one Git repository and split deployable applications into npm workspaces:

- `apps/web` — Next.js frontend and the framework-bound Auth.js boundary.
- `apps/api` — Fastify domain API, MongoDB/Mongoose persistence, services, repositories, and seed commands.
- `packages/shared` — framework-independent Zod contracts, types, and German vocabulary normalization.

Auth.js remains in `apps/web` during this structural phase because moving the identity provider would change authentication behavior. Domain data remains owned exclusively by `apps/api`.

## Objective

Make frontend and backend boundaries visually and operationally explicit without adding Phase 02 product behavior or changing existing MongoDB data.

## In scope

- npm workspace configuration and root orchestration scripts.
- Move the existing Next.js application and browser tests into `apps/web`.
- Move database, models, repositories, services, integration tests, and seed tooling into `apps/api`.
- Add a minimal Fastify server with `/api/v1/health` and CORS restricted to the configured web origin.
- Move reusable vocabulary validation and normalization into `packages/shared`.
- Preserve all Phase 00/01 tests and production seed behavior.
- Update repository documentation and environment placeholders for the split.

## Non-goals

- Vocabulary CRUD endpoints or UI.
- Authentication redesign, JWT issuance, or account migration.
- SRS scheduling and review endpoints.
- Any MongoDB schema or production data migration.
- Deployment, commit, or push.

## Acceptance criteria

- `npm run dev:web` starts the frontend on port 3000.
- `npm run dev:api` starts the backend on port 4000.
- The backend health route returns an explicit ready response.
- Frontend source does not import Mongoose, repositories, services, or database modules.
- Backend source does not import React, Next.js UI modules, or frontend components.
- Shared contracts contain no framework or database imports.
- Unit, integration, typecheck, lint, format, build, E2E, and dependency audit checks pass from the repository root.
- Production MongoDB still contains the four previously seeded A1 lessons and forty vocabulary items.

## Verification

1. Add an architecture-boundary test and observe it fail against the current single-app layout.
2. Move files and configure workspaces until the boundary test passes.
3. Run existing unit and Atlas integration tests from their new workspaces.
4. Run both application builds and verify both health endpoints.
5. Run the existing Playwright suite against `apps/web`.
6. Record observed results in `harness/build-log.md` and mark this phase complete only if all gates pass.

## Completion evidence

- The workspace split, local API runtime, unit/architecture tests, typecheck, lint, formatting, builds, E2E suite, and dependency audit pass.
- After the Atlas IP access list was updated, all five integration tests passed against the isolated `lingo_deutsch_test` database.
- A read-only production query confirmed that `lingo_deutsch` still contains four A1 lessons and forty vocabulary items.
- No Phase 02 product behavior, production data migration, commit, push, or deployment was introduced.
